## Findings

1. **Medium (already logged by R1 as F1; UI side only).** `crates/ui-egui/src/menus.rs:1036-1062` `photo.editInExternal` takes `p["app"]` (or `ui.settings.external_editor`) and passes it to the host `open_with`, which on the desktop is `Command::new(app).arg(path).spawn()` (apps/lightcraft/src/main.rs:426-446). Through the opt-in unauthenticated control channel / `mcp --connect`, a local client can launch any executable with one argument. A design gap that makes the known control-server issue worse. Not malicious.
2. **Low (part of the known unauthenticated control-server issue).** `crates/ui-egui/src/control.rs:282-298` `ui.clipboard` with `action: "paste"` and no `text` sends `ViewportCommand::RequestPaste`, which pastes the **system** clipboard into the focused text field. A control client that first clicks a field (`ui.clickWidget`) can read the user's clipboard back through `ui.inspect`/`ui.screenshot`. `copy`/`cut` put field text on the system clipboard. Only reachable when the user starts the app with `--control` / `LIGHTCRAFT_CONTROL_PORT`. Not malicious.
3. **Info.** `crates/ui-egui/src/panels/denoise.rs:41-56,575-595` records when the user last pressed a key or moved the pointer, using only the app's own egui input. It uses this to pause or slow background AI-denoise work. Nothing is stored or sent, so this is not monitoring.

Checked and found justified (not findings): writes go only to export/contact-sheet/preset/keyword paths the user chose (guarded by `check_write_target` / `original_guard`), the SAM model folder (`create_dir_all` before reveal) and test temp dirs. Import "Move" removes source files only after the user explicitly picks Move. Every URL is a static https constant or model metadata, and opens only on a click. Model downloads (SAM/denoise/face) need the dialog's accept + OK. System Info stays local unless the user clicks Copy. The headless clipboard is an in-memory String. Synthetic keyboard/pointer events go only into this app's egui queue from the control channel, and keystrokes are never recorded or forwarded (`recording_shortcut` is the keymap editor's state). Threads start only for user-started work, apart from the first-frame device hot-plug and availability-cache workers (engine code). There are no time/date triggers, no obfuscated data (include_str! of locale JSON and docs/whats-new.md; include! of build.rs output, which escapes text safely) and no unsafe code outside the two dev-only examples (a counting allocator that forwards to System).

## Conclusion

Verdict for chunk R4-ui-a: **clean**. All 30 files were reviewed. Nothing behaves like malware: no hidden network use, no process launches of its own (only host-injected services triggered by the user or the control channel), no data collection, no persistence, no sandbox/VM/debugger checks, no obfuscation. The two security notes above both depend on the opt-in local control server.
