## Cross-checks done
- No `unsafe`, `extern`, `asm!`, `#[link_section]`, `#[used]`, libloading, registry/LaunchAgent/cron/service code anywhere in scope (only `unsafe` = libc::clock_gettime in the dev-only example render_bench.rs).
- No socket/HTTP code in production files of this chunk. Model downloads (denoise/faces) only start on an explicit command with `acknowledged: true`, from built-in pinned URLs (faces also from the user's own catalog.json); transfer code is in model_download.rs / face_download.rs / lightcraft-fetch (other chunks). No command here sends library data anywhere.
- No date/time-triggered logic: SystemTime/Instant used for cache TTLs, timings, marker text; all dates found are test fixtures or doc strings. `random` = user-requested shuffle sort.
- No VM/sandbox/debugger detection. devices.rs lists mount folders only to find camera cards (DCIM).
- include_str!/include_bytes!: assets/camera-tone/sony-dro-off.json, assets/camera-profiles/*.json (readable JSON colour statistics), assets/fonts/Inter-SemiBold.ttf. No opaque blobs.
- Deletion paths in production: denoise/face model folders (validated id + manifest present), staged downloads, *.lcdn denoise cache in <library>/denoise, *.lcsp smart previews, imported LUT copies under <library>/Profiles, temp `.part` files. photo.delete / deletePermanently / emptyRecentlyDeleted / removeFolder / forgetLocal are catalog-only.
- Moves/renames of user files: folder.rename / folder.move (browse.rs), photo.rename (rename.rs), library.import mode=move (import.rs). All non-overwriting / verified, undoable. Reachable via MCP/control by design.

## Findings
1. Medium - export-to-arbitrary-path commands overwrite any file and skip the originals guard; keyword.export gives a near-arbitrary-content write primitive.
   - crates/engine/src/cmd/keywords.rs:448 `std::fs::write(path, &file.text)` (keyword.export), preset_files.rs:75 (preset.export), curves.rs:355 (curve.exportPresets).
   - None calls `Session::check_write_target` (used by export.contactSheet, merge previewPath and app.export) so they can overwrite a library original or any other user file (fs::write truncates/overwrites, no Unique/Skip policy).
   - Keyword list text = one keyword per line verbatim (catalog keywords.rs:464; only control chars, leading/trailing space, `[..]`, `{..}` excluded). So `keyword.create {name: "<any shell line>"}` + `keyword.export {path: "~/.bashrc"}` writes attacker-chosen lines into any file. Reachable by any MCP/control client (control server is opt-in loopback, already logged as unauthenticated; browser cross-protocol requests are reportedly rejected). Not malicious; a hardening gap. Fix: route through check_write_target and refuse to overwrite existing non-matching files / force the expected extension.
2. Low - folder.rename / folder.move accept any absolute folder, not just folders the library knows (browse.rs:164-197, 223-250). Never overwrites, refuses the library's own dir, undoable; but a remote client can relocate arbitrary user folders (e.g. ~/Documents).
3. Low - profile.import without a library writes `std::env::temp_dir()/lightcraft-<slug>.cube` with fs::write (lut_profiles.rs:112) - predictable name in shared /tmp, follows symlinks. profile.deleteImported uses lexical `starts_with(Profiles)` on a path from prefs (lut_profiles.rs:142).
4. Info - photo.duplicate has a small TOCTOU between `dst.exists()` loop and `std::fs::copy` (convert.rs:288-292), which overwrites if a file appears in between.
5. Info - keyword.import / curve.importPresets / preset.import / library.browse + photo.allMetadata let a command client read local files' contents (keyword lines, EXIF/GPS) back through command results. Local only; relevant only together with the known unauthenticated control channel.

## Conclusion
Verdict for chunk R2-engine-a: CLEAN (no malicious behaviour). Every file-system, download and thread capability matches the stated purpose (photo library, export, model management, caches). The one notable new issue is a hardening gap: several "export to path" commands write to any path without the originals guard, and keyword.export lets a command client write chosen text lines to any file.
